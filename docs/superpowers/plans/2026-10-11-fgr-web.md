# FastGraphRetriever Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A React web app that makes WL + ADR + AER retrieval visible: chat with cited evidence, a Retrieval Lab that compares modes, a benchmark page that reproduces the research numbers, medical note ingestion, and a graph explorer.

**Architecture:** Vite SPA (React 18 + TypeScript) talking only to the backend's `/api` (REST via TanStack Query, streaming via a fetch-based SSE reader). One shared selection store links citations, triple rows, trace ticks and graph nodes by triple key `h_eid:rid:t_eid`. Served by nginx, which proxies `/api` to the `api` container.

**Tech Stack:** Node 20, Vite 5, React 18, TypeScript (strict), Tailwind CSS 3.4, Radix UI primitives, TanStack Query 5, Zustand, Cytoscape.js 3 + cytoscape-fcose, Recharts, react-markdown + rehype-sanitize, i18next, lucide-react, @fontsource (Be Vietnam Pro, JetBrains Mono), Vitest + Testing Library + MSW, Playwright (via `.claude/skills/webapp-testing`).

**Spec:** `docs/UI_SPEC.md` (visual design and pages), `docs/API.md` (the contract), and `docs/superpowers/specs/2026-10-11-fastgraphretriever-design.md`. Backend plan: `docs/superpowers/plans/2026-10-11-fgr-backend.md`. Before this plan's Task 3, the backend's Task 10 must exist, or use the MSW mocks.

## Global Constraints

- Load `.claude/skills/frontend-design` before any visual work and follow its two-pass process: plan, review against the brief, build, critique with screenshots.
- Colour tokens exactly as UI_SPEC §2.1 (light/dark): `--ground #EDF1EF/#0F1B1E`, `--ink #16213A/#E2EBE7`, `--formalin #0F766E/#2DD4BF`, `--iodine #B45309/#F59E0B`, `--methylene #6D28D9/#A78BFA`, `--signal #B91C1C/#F87171`. Neutrals are `--ink` at 8/16/32/64% alpha.
- Fonts: Be Vietnam Pro (400/500/600) for text; JetBrains Mono only for relation ids, eids, MIDs, timings. Type scale 13/15/18/24/32 px. Sentence case; no all-caps labels; no eyebrow labels.
- Node encodings: anchor = formalin diamond; bridge = iodine hexagon; answer/cited = methylene ring; CVT = small hollow circle (ink 32%); other = ink 64% dot. At most 150 graph nodes drawn.
- All strings through i18next (`vi` default, `en`). No hard-coded UI text.
- The only network calls are to `/api/*` (dev: Vite proxy to `http://localhost:8000`). Never call an LLM or S3 from the browser.
- Identity is the triple key `${h.eid}:${r.rid}:${t.eid}` and the entity `eid`, never names (names are not unique).
- Motion only responds to actions, and must be instant under `prefers-reduced-motion`. Visible focus ring everywhere. WCAG AA contrast.
- Breakpoints: ≥ 1280 split view (evidence 58%); 768–1279 evidence drawer; < 768 tabs.

## Review Focus

- Very long names and relation ids (Freebase ids like `base.schemastaging.context_name.official_name`, long Vietnamese terms): cells truncate with a tooltip, chips wrap, and the layout never scrolls horizontally. Pinned in Task 2.
- A stream that ends without `done` (network drop, `error` event, server restart): the chat shows the error in plain words, keeps whatever already arrived, and re-enables the composer. Pinned in Task 5.
- An empty or truncated result (0 triples, `truncated: true`): an explicit empty state or notice, never a blank canvas. Pinned in Task 2.
- Changing mode, k or anchors while a request is in flight: the older request is aborted and only the latest result renders. Pinned in Task 3.
- Duplicate entity names in one result (two "The Illusion"): selection and highlighting follow eids, so clicking one does not light up the other. Pinned in Task 2.
